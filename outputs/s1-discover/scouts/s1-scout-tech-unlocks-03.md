# Scout tech-unlocks-03: on-device, open-weight, fine-tuning, long-context economics

## Findings

1. **Apple Foundation Models framework (Swift API to on-device LLM)** — Apple introduced a Foundation Models framework at WWDC25 giving app developers direct Swift access to the on-device ~3B-parameter Apple Intelligence model "with just a few lines of code," free of inference cost, for summarization/extraction/classification; not built for world knowledge or advanced reasoning. Date: 2025-06. Cap-card: capability=on-device text extraction/summarization API | first available=2025-06 (WWDC25) | maturity=production (shipped in iOS/macOS SDK) | cost=free (runs on user's Apple Silicon device) | unlock=indie iOS devs can add private AI features without a backend. Source: https://developer.apple.com/videos/play/wwdc2025/286/ — computer-centric: yes

2. **Chrome built-in AI / Gemini Nano ships in-browser** — "Chrome 138, rolling out from June 24, 2025, introduces built-in, on-device AI APIs powered by Gemini Nano ... for features like summarization, translation, and language detection, all without leaving the user's device." Chrome auto-downloads the model on first use and runs it via WebAssembly/WebGPU with no server calls. Date: 2025-06. Cap-card: capability=in-browser on-device LLM (Prompt/Summarizer/Writer APIs) | first available=2025-06 | maturity=production (GA in stable Chrome) | cost=free, local compute | unlock=web-app developers can add private text features with no cloud spend or user data leaving the browser. Source: https://developer.chrome.com/docs/ai/built-in — computer-centric: yes

3. **Gemini Nano gains CPU support (wider device reach)** — "CPU support for Gemini Nano is rolling out in Chrome 140. By enabling CPU inference on Linux, macOS, and Windows, many more users can benefit from the performance, privacy, and cost-effectiveness of built-in AI features," removing the prior GPU-only requirement. Date: 2025 (Chrome 140). Cap-card: capability=CPU-only on-device inference in browser | first available=2025 | maturity=production | cost=free | unlock=lower-spec Windows/Linux/macOS machines without a dedicated GPU can run local browser AI. Source: https://developer.chrome.com/blog/gemini-nano-cpu-support — computer-centric: yes

4. **OpenAI gpt-oss: first open-weight OpenAI models since GPT-2** — "OpenAI released gpt-oss-120b and gpt-oss-20b on August 5, 2025 under Apache 2.0." gpt-oss-120b has "116.83B total parameters / 5.13B active parameters" with a 131,072-token context window and "runs on a single 80GB GPU"; gpt-oss-20b has ~20.91B total/3.61B active params and "fits in 16GB of memory," matching o3-mini on core reasoning benchmarks. Date: 2025-08. Cap-card: capability=open-weight reasoning model, local-deployable | first available=2025-08 | maturity=production | cost=free weights, self-hosted compute | unlock=a small team can self-host a frontier-adjacent reasoning model on one workstation-class GPU or a 16GB machine, keeping prompts and outputs off any vendor's servers. Source: https://openai.com/index/introducing-gpt-oss/ — computer-centric: yes

5. **Gemma 3 open-weight family, 128K context, quantized for edge** — "Gemma 3 is a family of open-weight large language models developed by Google DeepMind and released on March 12, 2025," in four sizes (1B, 4B, 12B, 27B); the 4B/12B/27B models ship with a 128K context window (1B stays at 32K), and Google released quantized versions to cut compute further, aimed at running on phones and laptops. Date: 2025-03. Cap-card: capability=small open-weight multilingual model family | first available=2025-03 | maturity=production | cost=free weights, runs on consumer hardware | unlock=developers building phone/laptop apps that need local long-context text understanding without a cloud bill. Source: https://venturebeat.com/ai/google-unveils-open-source-gemma-3-model-with-128k-context-window — computer-centric: yes

6. **Copilot+ PC NPU threshold: 40+ TOPS for on-device AI** — "Many of the new Windows AI features require an NPU with the ability to run at 40+ TOPS," a bar met by Intel Core Ultra 200V (48 TOPS), AMD Ryzen AI 300 (50 TOPS), and Qualcomm Snapdragon X Elite (45 TOPS) chips; this lets "certain Copilot experiences run locally instead of in the cloud," cutting latency and extending battery life. Date: 2025 (per Windows Forum roundup of 2025 laptop hardware). Cap-card: capability=NPU-accelerated local inference on Windows laptops | first available=2024-2025 hardware generation | maturity=production | cost=built into laptop purchase price | unlock=Windows software vendors can ship offline transcription/image/text AI features to a growing base of "AI PCs." Source: https://windowsforum.com/threads/copilot-pcs-and-npus-redefining-the-2025-best-ai-laptop-with-40-tops.389452/ — computer-centric: yes [unverified: exact TOPS figures not cross-checked against a Microsoft primary source]

7. **Unsloth/QLoRA cuts fine-tuning cost to single-digit dollars** — "QLoRA on a single H100 takes 8-12 hours and costs $10-16," and "a LoRA fine-tune on a 7B model costs under $10, while a 70B QLoRA run costs $15-30"; separately, a Llama 3.3 8B fine-tune needs "8 GB VRAM and 1-2 hours on consumer hardware using Unsloth," which the vendor says gives "up to 2x training speedup." Date: 2025-2026 (blog aggregation, exact publish date not shown). Cap-card: capability=cheap LoRA/QLoRA fine-tuning tooling | first available=tooling matured through 2025 | maturity=production | cost=$10-30 per fine-tune run, or free on a personal GPU | unlock=a two-person team can custom-tune a model on proprietary text for well under $50 instead of needing an ML infra budget. Source: https://www.promptquorum.com/local-llms/fine-tuning-local-llms-lora — computer-centric: yes [unverified: aggregator page, not a primary vendor pricing page]

8. **OpenAI hosted fine-tuning pricing (concrete $/M tokens)** — "GPT-4o-mini fine-tuning training costs $3.00 per million tokens" and "Fine-tuned GPT-4o-mini inference costs $0.30 per million input tokens and $1.20 per million output tokens," roughly double the base GPT-4o-mini rate of $0.15/$0.60. Also noted: "OpenAI is winding down the fine-tuning platform as of May 2026 and it's no longer open to new users," though existing users can still fine-tune GPT-4.1-mini and o4-mini (reinforcement fine-tuning). Date: pricing as of 2025, deprecation dated 2026-05. Cap-card: capability=hosted supervised fine-tuning | first available=pre-existing, priced through 2025 | maturity=production (being sunset for new users in 2026) | cost=$3/M training tokens, ~2x inference cost | unlock=teams without GPU infra can customize a hosted model cheaply, though this specific path is closing to new entrants. Source: https://the-rogue-marketing.github.io/openai-api-updates-and-pricing-october-2025/ — computer-centric: yes [unverified: secondary aggregator, cross-check against openai.com pricing recommended]

9. **Long-context pricing lands on Gemini and Claude 1M-token tiers** — "Gemini is the first model capable of accepting 1 million tokens"; "Gemini 2.5 Flash ... 1M token context window at $0.15 input / $0.60 output per 1M tokens." Separately Anthropic's long-context Opus tier is reported at "$5.00 input / $25.00 output per 1M tokens" for a 1M-token window. Date: pricing snapshot 2025-2026. Cap-card: capability=1M-token context window | first available=2025 (Gemini 2.5 generation) | maturity=production | cost=as low as $0.15/M input tokens on a cheap tier | unlock=ingesting an entire contract set, codebase, or patient chart history in a single prompt without chunking pipelines. Source: https://www.datastudios.org/post/google-gemini-context-window-token-limits-model-comparison-and-workflow-strategies-for-late-2025 — computer-centric: yes [unverified: pricing figures for later-dated model names (e.g. "Claude Opus 4.7," "Gemini 3.x") could not be independently confirmed against a primary vendor pricing page and may reflect a fast-moving or aggregator-projected price list]

10. **LLM inference cost collapse, ~10x/year** — "Andreessen Horowitz has coined the term 'LLMflation'... the cost for an LLM of equivalent performance falls about 10x per year," published 2024-11-12. Epoch AI's independent tracking (2025-03) found "drops of 9-900x per year across six performance benchmarks," with "GPT-3-quality output that cost $60 per million tokens in late 2021" selling "for $0.06 by late 2024" — a roughly 1,000x fall in three years. Date: 2024-11 (a16z) / 2025-03 (Epoch AI). Cap-card: capability=commodity-priced inference at fixed quality | first available=ongoing trend through 2025 | maturity=production | cost=sub-$1/M tokens for GPT-3-era quality | unlock=high-volume, low-margin use cases (bulk document triage, customer support drafts) become affordable for small teams. Source: https://epoch.ai/publications/the-plunging-price-of-thought — computer-centric: yes

11. **Washington State Bar: consumer AI tools barred when confidentiality can't be assured** — "In instances where protection of client confidential information cannot be reasonably assured, lawyers should not use consumer-oriented AI tools," per a 2025 advisory opinion; law-tailored products need "contractual assurances of confidentiality consistent with lawyers' duties under RPC 1.6." Date: 2025 (Advisory Opinion 2025-05). Cap-card: n/a (regulatory finding, not a technical capability). Who it affects: solo/small-firm lawyers choosing between cloud AI vendors and local models. Source: https://www.wsba.org/docs/default-source/legal-community/committees/committee-on-professional-ethics/ao-202505.pdf — computer-centric: yes

12. **NYC Bar formal opinion on AI recording/transcribing client calls** — NYC Bar's "Formal Opinion 2025-6" concludes "an attorney should obtain client consent before recording the call" when AI is used "to record, transcribe and create a summary of the conversation," and must weigh "confidentiality and privilege" before relying on AI transcripts. Date: 2025. Who it affects: attorneys evaluating AI meeting-notes tools; pushes toward tools that can guarantee where audio/text is processed. Source: https://www.nycbar.org/reports/formal-opinion-2025-6-ethical-issues-affecting-use-of-ai-to-record-transcribe-and-summarize-conversations-with-clients/ — computer-centric: yes

13. **Local AI workflow pattern for therapists' clinical notes** — A vendor write-up describes "a practical, HIPAA-aligned local AI workflow for licensed therapists" using "Whisper transcription and Llama 3.1 SOAP drafting with no cloud services," architected with "TLS encryption, Nginx reverse proxy, Open WebUI ... and Ollama server on a LUKS-encrypted volume," explicitly to keep PHI from leaving the practice's own network. Date: not explicitly dated on page (2025-2026 content, referencing Llama 3.1/Ollama/Open WebUI stack). Cap-card: capability=fully offline speech-to-note pipeline | first available=components (Whisper, Llama 3.1, Ollama, Open WebUI) matured through 2024-2025 | maturity=demo/small-practice grade, not a packaged clinical product | cost=self-hosted hardware only | unlock=solo therapists and small clinics can draft session notes without a BAA-covered cloud vendor. Source: https://localaimaster.com/blog/local-ai-therapists — computer-centric: yes [unverified: vendor content, exact publish date and independent replication not confirmed]

14. **Accountants asking to keep financial data off vendor servers** — "Accountants frequently ask: 'Can I run AI on my own hardware so my clients' financial data never leaves the building?'" the same source notes "for many firms it's the wrong place to start," i.e., local deployment is harder than tutorials suggest, and cites "Ollama, LM Studio, and llama.cpp" as the enabling toolchain. Date: content dated 2026 on the page but describing a persistent 2025-2026 concern. Cap-card: n/a (demand signal). Who it affects: small accounting/bookkeeping firms handling bank statements, payroll, W-2s. Source: https://jupid.com/blog/local-llm-for-accounting — computer-centric: yes [unverified: vendor blog, not a primary survey or forum quote]

15. **llama.cpp materially faster than Ollama on identical GGUF weights** — "On an RTX 5090 with the same GGUF file, llama.cpp generated 249 tokens per second against Ollama's 108," and more broadly "llama.cpp is faster than Ollama — by 10.3% on an RTX 5060 Ti (77.0 vs 69.1 tokens/sec) and by about 14% on an Apple M3 Max (53.5 vs 46.2 tok/s)." GGUF Q4_K_M quantization "reduces memory usage by about 75%, while maintaining nearly the same quality (less than 1% loss)." Date: benchmark page, 2025-2026 (exact date not shown). Cap-card: capability=fast local inference engines | first available=llama.cpp/Ollama both mature by 2024, benchmarked through 2025-2026 | maturity=production | cost=free, consumer GPU | unlock=a small team can serve a quantized model at 50-250 tokens/sec on a single consumer GPU, no cloud inference bill. Source: https://inventivehq.com/blog/ollama-vs-llama-cpp-vs-lm-studio-benchmark — computer-centric: yes [unverified: exact publish date not confirmed]
