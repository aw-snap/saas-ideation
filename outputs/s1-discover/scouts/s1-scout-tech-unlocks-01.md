# Scout tech-unlocks-01: computer-use and browser agents

## Findings

1. **Anthropic computer use (original beta)** — Claude 3.5 Sonnet gained the ability to "view a screen, move a cursor, click, and type," released as an API beta. Quote: "still cumbersome and error-prone." Scored 14.9% on OSWorld screenshot-only category (vs. next-best system's 7.8%), 22.0% with extra steps. Date: 2024-10 (pre-window, included for baseline only). Cap-card: computer-use API tool | 2024-10 | demo-grade | same token price as Claude 3.5 Sonnet | any team scripting screen-level automation via API. Source: https://www.anthropic.com/news/3-5-models-and-computer-use — computer-centric: yes.

2. **Claude Sonnet 4.5 computer-use jump** — OSWorld score rose to 61.4% from Sonnet 4's 42.2% four months earlier, a claimed benchmark lead. Quote: "now leads at 61.4%." Model can "maintain focus for more than 30 hours on complex, multi-step tasks." Pricing unchanged at $3/MTok input, $15/MTok output. Date: 2025-09-29. Cap-card: computer-use (Claude Agent SDK) | 2025-09 | moving toward production | $3 in / $15 out per MTok | dev teams building long-running screen agents. Source: https://www.anthropic.com/news/claude-sonnet-4-5 — computer-centric: yes.

3. **Claude for Chrome extension rollout** — Browser extension letting Claude click, fill forms, and manage email/calendar. Piloted with 1,000 Max users (2025-08), expanded to all Max users (2025-11), then Pro/Team/Enterprise (2025-12). Included in existing subscription, no separate line-item price disclosed. Cap-card: in-browser agent | 2025-08 (pilot) / 2025-12 (broad) | production for consumer/enterprise tiers | bundled with Claude subscription | knowledge workers automating routine browser chores. Source: https://claude.com/blog/claude-for-chrome — computer-centric: yes.

4. **Prompt-injection attack rates on browser agents** — Anthropic's own red-teaming found "23.6% attack success rate when deliberately targeted by malicious actors" before mitigations; reduced to 11.2% in autonomous mode after fixes, and specialized browser attacks cut "from 35.7% to 0%" for four attack types. Date: 2025 (Claude for Chrome launch period, per the same blog). Cap-card: security risk, not a capability | n/a | n/a | n/a | relevant to anyone giving an agent real browser credentials. Source: https://claude.com/blog/claude-for-chrome — computer-centric: yes.

5. **Gemini 2.5 Computer Use model, public preview** — Built on Gemini 2.5 Pro visual reasoning; loop of screenshot-in, UI-action-out. Reported to lead on Online-Mind2Web and WebVoyager benchmarks and perform strongly on AndroidWorld, with "leading quality for browser control at the lowest latency." Explicitly "not yet optimized for desktop OS-level control" — browser only. Date: 2025-10-07 (public preview via AI Studio / Vertex AI). Cap-card: browser/mobile UI control model | 2025-10 | preview (not GA) | pricing not disclosed [unverified] | teams needing low-latency web-only agents, not full desktop control. Source: https://deepmind.google/models/gemini/computer-use/ (via WebFetch summary) — computer-centric: yes.

6. **browser-use open-source framework scale** — MIT-licensed Python library controlling browsers via LLMs; GitHub shows 116.2k stars and 10,295+ commits (checked 2026-09). Offers a hosted Cloud API priced at "$0.02 per browser-hour" with a "$15 cloud credit" for new signups. Maintains a "Browser Use Benchmark v2" for harder tasks, noting "on easier tasks, even smaller models can achieve very high success rates" (no exact % given). Cap-card: open-source browser agent SDK | ongoing since 2024, still actively shipping through 2025-2026 | production-adjacent (widely deployed, self-reported benchmark not peer audited) | free (OSS) or $0.02/browser-hour cloud | indie devs and small teams automating any web workflow cheaply. Source: https://github.com/browser-use/browser-use — computer-centric: yes.

7. **Skyvern targets no-API legacy portals directly** — Open-source (AGPL-3.0) platform extending Playwright with LLM + computer vision; 23.1k stars, 6,805 commits. Explicitly lists government portal account registration/forms, insurance quote retrieval (names Geico, BCI Seguros), invoice downloads across sites, and job applications as use cases. On the WebBench benchmark: "Overall accuracy: 64.4%," with best-in-class performance on WRITE-class tasks (forms, logins, file downloads) among competing agents. Cap-card: browser agent for legacy/no-API sites | ongoing (repo mature, 2024-2026) | production-adjacent, self-hosted or "Skyvern Cloud" | pricing for cloud not disclosed [unverified], OSS free | ops teams driving insurance and government portals without APIs. Source: https://github.com/Skyvern-AI/skyvern — computer-centric: yes.

8. **UI-TARS: open GUI-agent model family with real OSWorld numbers** — UI-TARS-1.5 (2025-04-16) scored OSWorld 42.5% (100 steps), Windows Agent Arena 42.1% (50 steps), WebVoyager 84.8%, AndroidWorld 64.2%, ScreenSpotPro grounding 61.6%. UI-TARS-2 announced 2025-09-04. Repo has 11.5k stars, 883 forks. Cap-card: open-weight GUI grounding + action model | 2025-04 (v1.5) / 2025-09 (v2) | research-grade moving to production use in agent stacks | self-hostable, free weights | teams needing a local/open model for desktop + mobile + browser GUI control. Source: https://github.com/bytedance/UI-TARS — computer-centric: yes.

9. **Stagehand SDK abstracts browser agents into dev-friendly API** — TypeScript/Python/Go SDK adding `act()`, `observe()`, `extract()` on top of Playwright; 25.4k stars, 1,537 commits, by Browserbase. Claims "2x faster execution than Playwright cloud equivalent browsers" when paired with Browserbase's hosted infra (unverified independent number). Cap-card: browser-agent dev SDK | ongoing (copyright shows active 2026 development) | production (integrates with Claude Code, MCP, CrewAI, Mastra) | free OSS, paired with paid Browserbase cloud | developers wiring natural-language browser steps into existing Playwright codebases. Source: https://github.com/browserbase/stagehand — computer-centric: yes.

10. **Browserbase infrastructure scale signals real paid demand** — Hosted headless-browser infra for agents reports "35 million+ browser sessions monthly," "10,000+ customers," "800,000 weekly SDK downloads," "100,000 developers," and named enterprise customers/case studies including Microsoft, Ramp, Amplitude, and Lovable. Amplitude engineer quote: "Not worrying about all that infra work and focusing directly on the impact I can bring to our sales teams was a huge unblock." Cap-card: cloud browser/sandbox infra for agents | ongoing through 2026 | production, paying enterprise customers | pricing not disclosed on page [unverified] | dev teams that don't want to run their own browser fleet for agents. Source: https://www.browserbase.com/ — computer-centric: yes.

11. **OSWorld as the reference desktop-agent benchmark** — Multiple vendors (Anthropic, UI-TARS) report scores on OSWorld as the standard yardstick for "can an agent actually operate a real desktop OS," with scores climbing from teens/twenties in late 2024 to 60%+ by late 2025 for top models — still well under 100%, meaning most real desktop tasks still fail a meaningful fraction of the time. Cap-card: n/a (benchmark, not a product) | n/a | n/a | n/a | anyone estimating current agent reliability ceiling. Source: cross-referenced from findings #1, #2, #8 (Anthropic and UI-TARS release pages) — computer-centric: yes.

12. **Gemini computer use explicitly excludes desktop OS control** — Google states the model is "primarily optimized for web browsers" and "not yet optimized for desktop OS-level control," a direct maturity gap versus Anthropic's and UI-TARS's desktop-capable computer-use tools. Date: 2025-10. Cap-card: gap, not capability | n/a | preview-only scope limit | n/a | relevant to anyone needing non-browser (native app) automation. Source: https://deepmind.google/models/gemini/computer-use/ — computer-centric: yes.

13. **Anthropic's own framing of computer use as unreliable at launch** — The original 2024-10 announcement itself cautions the capability is "still cumbersome and error-prone," a self-reported reliability admission from the vendor closest to the tech, useful as a baseline against the 2025-09 jump to 61.4% OSWorld. Source: https://www.anthropic.com/news/3-5-models-and-computer-use — computer-centric: yes.

## Who it helps (backward map)
- Insurance/ops staff manually re-keying quotes across carrier portals — screen workflow: logging into no-API insurer sites to pull quotes — findings #7
- Government-services or benefits caseworkers filling repetitive portal forms — screen workflow: account registration and form submission on government portals — findings #7
- Small dev teams without RPA budgets — screen workflow: scripting browser tasks in natural language instead of brittle selectors — findings #6, #9
- Enterprise knowledge workers on Claude Max/Pro/Enterprise — screen workflow: routine browser chores (forms, email, calendar) inside their existing browser — findings #3
- Teams needing to self-host or fine-tune a GUI-control model for privacy/cost reasons — screen workflow: desktop, mobile, and browser GUI grounding — findings #8
- Security/IT teams evaluating whether to grant agents browser credentials — screen workflow: risk review before deploying an autonomous browser agent — findings #4
